§1

The eight data types

Every value in JavaScript is one of eight types. Seven are primitives — simple single values. One is object — anything made of other values.

typewhat it holdsexample
numberany number, whole or decimal42   3.14   -7
stringtext"hello"
booleanonly two values evertrue   false
undefineddeclared, but nothing put in it yetlet x;
nulldeliberately emptynull
bigintnumbers too big for number9007199254740993n
symbola guaranteed-unique identifierSymbol("id")
objecta collection of values{ }   [ ]   functions

You only need four of these day to day — number, string, boolean and object. undefined and null show up often but you rarely write them. bigint and symbol you may not use for months. Learn the names; don't drill them.

undefined vs null

undefined means nobody has put a value here yet — JavaScript does this for you. null means someone deliberately set it to empty. The difference is intent.

And a famous wart: typeof null returns "object". That is a bug from 1995 that can never be fixed without breaking the web. Just know it.

§3

What a method is

The lesson's own definition: a method is a bit of functionality built into the language or a specific data type.

In practice: a method is an action you run on a value, written with a dot after it and parentheses at the end.

"hello".toUpperCase()
 |         |         |
 |         |         +-- parentheses: DO it now
 |         +------------ the method - the action
 +---------------------- the value you are acting on

Strings come with dozens built in. You do not memorise them — you learn the half dozen you use constantly and look up the rest.

string methods
press Run

length is the odd one — no parentheses

"hello".length has no (), because it is a property (a fact about the value), not a method (an action). Facts you just read; actions you have to run.

§4

Comparison operators

These ask a question and always answer true or false. They are the fuel for every conditional in §7.

opasksexampleanswer
===same value and same type?5 === 5true
===5 === "5"false
!==not strictly equal?5 !== "5"true
==same value, ignoring type5 == "5"true
>greater than5 > 3true
<less than5 < 3false
>=greater than or equal5 >= 5true
<=less than or equal3 <= 5true

=== not ==, and never =

Three different things. = assigns a value. == compares loosely, converting types first. === compares value and type.

Use === by default. == produces surprises like 0 == "" being true. And writing = inside an if is a classic bug — it assigns instead of asking.

§6

Truthy and falsy

An if does not need an actual true. It takes any value and decides whether it counts as true. A value that counts as true is truthy; one that counts as false is falsy.

There are exactly eight falsy values. Everything else in the entire language is truthy. Learn the short list and you know the whole rule:

falsywhat it is
falsethe boolean
0zero
-0negative zero
0nbigint zero
""an empty string
null
undefined
NaN"not a number"

Try any value

The ones that catch people

"0" is truthy — it is a string with a character in it, not the number zero. [] and {} are truthy too, even though they are empty. Only that list of eight is falsy.

§7

Conditionals, and nesting

The lesson's framing is worth keeping: the essence of programming is teaching the computer how to make decisions. Conditionals are how.

if / else if / else

if (score >= 90) {
  grade = "A";
} else if (score >= 80) {
  grade = "B";
} else {
  grade = "F";
}

JavaScript checks each condition top to bottom and runs the first one that is true, then skips the rest. Move the slider and watch which branch is taken:

score 85

Nesting

Nesting means putting one thing inside another — an if inside another if. The inner one is only reached if the outer one was true.

if (loggedIn) {
  if (isAdmin) {          // only checked when loggedIn is true
    console.log("admin panel");
  } else {
    console.log("normal user");
  }
} else {
  console.log("please log in");
}

Keep nesting shallow. Two levels is usually fine; four is a sign the logic wants rearranging — often with && instead.

switch — for many fixed options

switch (day) {
  case "Sat":
  case "Sun":
    console.log("weekend");
    break;              // without break it falls through!
  default:
    console.log("weekday");
}

switch compares one value against fixed options. It uses strict comparison, like ===. Forgetting break is the classic bug — execution continues into the next case.

§8

Assignment — the exercises

This lesson's assignment is the first time you use The Odin Project's exercise repository, which runs automated tests against your code. It is a step up from typing into a console — and it is worth the setup, because from here on the exercises use it.

One-time setup

Follow the README in TheOdinProject/javascript-exercises: fork it on GitHub, clone your fork, then install the test runner.

# after forking on GitHub, in your terminal:
git clone https://github.com/YOUR-USERNAME/javascript-exercises.git
cd javascript-exercises
npm install                 # installs Jest, the test runner

Then work in foundations/data_types_and_conditionals. Read each exercise's README before starting it, and run its tests with:

npm test 01_helloWorld

Node, not the browser

These exercises run in Node from your terminal, not in a browser. So you need Node installed — and you will see red failing tests before you see green passing ones. That is the intended workflow: run, read the error, fix, run again.

The lesson's own advice: "Read all the directions, watch the terminal, and read all the errors."

The five, in order

01_helloWorld

Deliberately trivial — it exists to confirm your setup works. If this one passes, everything is installed correctly.

02_addNumbers

Add two numbers and return the result. Your first taste of return — the function hands a value back instead of logging it.

03_numberChecker

Compare numbers and return different strings. This is §4 and §7 together — comparison operators inside a conditional.

04_mathEquations

More arithmetic, with attention to what you return.

05_joinStrings

String work — §2 and §3.

Solutions live in each exercise's solution folder. Use them to check, not to start.

About return, since it appears before it is taught

The lesson admits this: "Anywhere you see return, it just means that when the function finishes running, it will spit back whatever comes after return."

console.log prints a value for a human to look at. return hands it back so other code can use it. The tests check what you return — logging will not make them pass.
