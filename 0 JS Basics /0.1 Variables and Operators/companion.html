§1

How to run JavaScript code

All the JavaScript in Foundations runs in the browser. The simplest way to start is an HTML file with the code inside a <script> tag. In VS Code, ! then TAB gives you the skeleton.

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Document</title>
</head>
<body>
  <script>
    // Your JavaScript goes here!
    console.log("Hello, World!")
  </script>
</body>
</html>

Seeing the output

Save it, open it in a browser, then open the console:

1Right-click on the blank webpage
2Click Inspect or Inspect Element to open the Developer Tools
3Find and select the Console tab — your console.log output is there

console.log() prints something to that console. It is how you see anything at all before you learn to put things on the page itself.

The other way — an external file

<script src="javascript.js"></script>

JavaScript files end in .js, just as stylesheets end in .css. The name is up to you — javascript.js, my-script.js, anything. External files are used for more complex scripts.

Both files are already in this folder

index.html has the skeleton with the script tag. javascript.js is there if you would rather use an external file. Open index.html in your browser and check the console says Hello, World!

The console on this page works the same way, so you can try things here first without switching windows.

§2

Variables

Variables are the building blocks of any program. Think of them as storage containers for data in your code.

let — can be re-assigned

let age = 11;
console.log(age);  // outputs 11
age = 54;         // no `let` here - it already exists, we are just re-assigning
console.log(age);  // what will be output now?

Notice the missing let on line 3. You declare a variable once; after that you just assign to it.

const — cannot be re-assigned

const pi = 3.14;
pi = 10;
console.log(pi);   // what will be output?

Your intuition may say 3.14. Run it below and see. An error is thrown — it does not even reach the console.log.

try it
press Run

Why an error is a good thing

You may wonder why we would want an error. Errors are incredibly helpful — they tell you what is wrong and exactly where. Without them the code would still misbehave, but finding the cause would be a major pain.

So, two ways to declare a variable

keywordre-assign?use it when
letyesthe value will change
constno — throwsthe value should never change
varyesdon't — see below

There is a third way, var — the original way variables were declared. It is similar to let, but has quirks that let and const cleared up. By and large it is not used any more, but you will come across it in older code, so it is worth knowing it exists.

§3

Numbers

It is hard to think of a useful programming task that does not involve at least a little maths. Happily, numbers in JavaScript behave much as you would expect.

Order of operations

JavaScript follows the standard mathematical order — PEMDAS / BODMAS:

#stepdirection
1Parentheses (brackets)innermost first
2Exponentiation **right to left
3Multiplication and Divisionleft to right
4Addition and Subtractionleft to right

The lesson's example: (3 + 2) - 76 * (1 + 1). Press the stepper to watch it resolve in that order.

press step
try any expression
press Run

One thing that will surprise you later

0.1 + 0.2 does not give 0.3. Run it above. This is not a JavaScript bug — it is how computers store decimals, and every language does it. You do not need to fix it yet; just do not panic when you see it.

Operators

An operator is a symbol that does something to values. You have met + already. Here is the rest of what this lesson expects.

Mathematical

opdoesexampleresult
+add (or join text)7 + 310
-subtract7 - 34
*multiply7 * 321
/divide7 / 32.333…
%remainder after dividing7 % 31
**to the power of7 ** 249

% is the one people have not met at school. It gives you what is left over. It is how you test whether a number is even: n % 2 === 0.

Assignment shortcuts

shortmeans

x++x = x + 1

Comparison — these give you true or false

opasksexampleresult

Use === and not ==

== quietly converts types before comparing, which produces surprises like 0 == "" being true. === checks the type too, so it does what you meant. Default to three equals signs until you have a specific reason not to.

§7

Assignment — the reading

Four articles. Two of them carry the material the lesson body skipped — strings and operators — so these are not optional extras.

MDN — What is JavaScript?

To understand the role of JavaScript on a webpage.

  • Big picture: HTML is structure, CSS is style, JavaScript is behaviour. Skim it — you do not need to retain details.

JavaScript.info — Variables

Deeper on the thing you just met.

  • The "box with a name on it" analogy for a variable.
  • Naming rules: letters, digits, $ and _; cannot start with a digit; case-sensitive (apple and APPLE are different).
  • Name things properly. userName beats a. This matters more than it sounds.
  • Constants in UPPER_CASE for values known before the program runs, such as COLOR_RED.

MDN — Basic math in JavaScript

The same ground from a different angle, plus how to apply it.

  • The arithmetic operators, including % (remainder) and ** (exponent).
  • Operator precedence — the PEMDAS table in §3.
  • Increment/decrement ++ --, and the assignment shortcuts += -=.
  • Comparison operators, and why === is the one to reach for.

JavaScript.info — Basic operators, maths

Code along with it — and do the Tasks at the bottom. The lesson says not to skip them.

  • Terms: an operand is what an operator works on; + with two is binary, with one (like -x) is unary.
  • String concatenation with + — if either side is a string, the result is a string. "1" + 2 is "12".
  • But - and * convert to numbers instead: "6" - "2" is 4. This asymmetry catches everyone once.
  • Unary + converts to a number — +"5" is 5. A quick alternative to Number().
  • Operator precedence, and that assignment = is itself an operator that returns a value.
