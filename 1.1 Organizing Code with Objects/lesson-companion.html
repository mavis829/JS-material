§1

Refresher

There are multiple ways to define objects, but in many cases object literal syntax is used. There are two ways to get information out of an object: dot notation and bracket notation.

const myObject = {
  property: "Value!",
  otherProperty: 77,
  "obnoxious property": function() {
    // do stuff!
  },
};

const variable = "property";

Dot notation is cleaner and is usually preferred, but there are plenty of circumstances when it is not possible. Run the last two buttons back to back — that is the trap.

Two cases where dot notation will not work

1. myObject."obnoxious property" won't work, because that property is a string with a space in it.

2. You cannot use variables in dot notation. myObject.variable is undefined because it looks for a property literally named variable. myObject[variable] is equivalent to myObject["property"].

Objects as a data structure

Storing related information with key/value pairs — one of the simplest ways to begin organizing your code. The lesson's tic tac toe example, with and without objects.

Without objects

With objects

Benefit 1 — namespacing

Normally name and marker would not be reusable in the same scope. Via namespacing, we can still use them — as playerOne.name and playerTwo.marker.

Benefit 2 — passing the data around

Instead of separate parameters for the name and the marker, gameOver takes one parameter for the entire object and has access to every property within.

function gameOver(winningPlayer) {
  console.log("Congratulations!");
  console.log(`${winningPlayer.name} (${winningPlayer.marker}) is the winner!`);
}

Press add a "wins" property, then run gameOver again. The function was never touched — because we passed the whole object in, rather than individual parameters.

Objects as a design pattern

The grouping power of objects is useful for organizing functionality as well. This is one of the core tenets of Object Oriented Programming (OOP) — a paradigm based on objects, which can contain data and code.

The two design questions

To describe any thing as an object, ask: "What properties (physical or conceptual) does my thing have?" → these become properties. And "How can I interact with it?" → these become methods.

const car = {
  make: "Volkswagen",
  model: "Golf",
  year: 2026,
  color: "blue",
  priceUSD: 40000,

  // a method is just a function assigned to a property
  applyDiscount: function(discountPercentage) {
    const multiplier = 1 - discountPercentage / 100;
    this.priceUSD *= multiplier;
  },

  // shorthand way to add a method to an object literal
  getSummary() {
    return `${this.year} ${this.make} …`;
  },
};
car
properties (data / fields) methods (code / procedures)

The this keyword

The this keyword is used to refer to the object a particular method is called from. It can be used to read and assign properties in exactly the same way as any other variable that points to an object.

applyDiscount assigns with this.priceUSD *= multiplier. getSummary reads with ${this.year}. Watch priceUSD in the object change when you apply the discount.

Lesson note — Arrow functions and "this"

The this keyword behaves differently inside arrow functions compared to traditional function expressions (which includes the shorthand syntax). We don't need to dive into how or why it differs yet — just know that if you used arrow functions in the example above, they would not behave as you expect.

§4

Objects for more abstract concepts

Moving past physical items, we can describe something more abstract — a game. Rock Paper Scissors involves players' scores and the ability to play a round (which should update a player's score), plus two nice-to-haves: determining the current winning player, and restarting the game.

const rps = {
  playerScore: 0,
  computerScore: 0,

  playRound(playerChoice) {
    // code to play the round, update score
    // if needed, then return the result
  },
  getWinningPlayer() {
    // return the player with the most points
    // ("player", "computer", or "tie")
  },
  reset() {
    // reset both players' scores to 0
  },
};
rps
properties methods

The two design questions still work on a thing with no physical form. playerScore and computerScore answer "what properties does it have?"; playRound, getWinningPlayer and reset answer "how can I interact with it?"

Lesson note — Underscore properties

A property starting with _ is purely a developer convention indicating the property is intended to be "private" — meant only for internal use, not to be read or called outside the object itself (such as helper methods).

JavaScript does not actually have the concept of real private properties for objects, at least not for object literals. Developers historically added a leading _ to indicate a property should be treated as if it was private, even though technically it is still accessible outside the object — "public".

§6

Knowledge check

An opportunity to reflect on the key topics. You are not expected to memorize or master this knowledge.

What are two ways you can use objects to organize code?

As a data structure — storing related information in key/value pairs, which gives you namespacing and lets you pass grouped data around as a single thing (playerOne). And as a design pattern — organizing functionality by storing logic as methods alongside the data they act on, which is a core tenet of OOP (car, rps).

What is a method?

A function that is part of an object — a function assigned to a property. In OOP terms, an object's code, in the form of procedures, as opposed to its fields/properties, which hold the data.

In object methods, what is the this keyword used for?

To refer to the object a particular method is called from. It is used to read and assign that object's properties in exactly the same way as any other variable pointing to an object — this.priceUSD *= multiplier assigns, ${this.year} reads.
